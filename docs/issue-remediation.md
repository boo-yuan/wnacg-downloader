## 2026-08-03 深度复审追加整改

在原 47 项基础上重新从并发、网络边界、文件所有权、生命周期、架构和供应链复审。以下问题均已纳入代码与门禁，不以旧记录中的“已修复”状态代替重新验证。

| 类别 | 复审发现 | 整改结果 |
|---|---|---|
| 并发一致性 | 队列读取后启动存在重复领取窗口 | SQLite 使用 `BEGIN IMMEDIATE` 和条件更新原子领取任务。 |
| 进度一致性 | 并发图片完成可能丢失递增或倒序持久化 | 每任务聚合锁下原子更新三个进度字段并串行写库。 |
| 领域不变量 | `progress=0` 可掩盖非零下载计数，赋值失败可能污染对象 | 全量聚合校验；计数只允许通过原子方法替换，并添加回归测试。 |
| 数据库完整性 | 未来 schema 可能被旧程序误写，约束不足 | 拒绝未来版本；表约束与 INSERT/UPDATE 触发器双重校验。 |
| 数据恢复 | 单条损坏记录可阻断整个任务列表 | 损坏行隔离、记录结构化错误并继续加载其余记录。 |
| SSRF/重定向 | HTTPS 字符串仍可能指向私网，重定向可跨边界 | URL、DNS 结果、最终响应 URL 均校验为公网 HTTPS；官方接口再限制主机。 |
| 响应资源耗尽 | HTML、更新 JSON、封面、单图或整本可无限增长 | 所有读取改为流式硬上限，并限制图片数、任务字节、像素和磁盘余量。 |
| 内容欺骗 | 非图片响应可能以图片扩展名落盘 | 校验 Content-Type，并由 Pillow 完整解码和像素预算复核。 |
| 下载完整性 | 直链接口失败后可能误判完成 | 失败或数量不符强制回退分页抓取，并与已知图片数核对。 |
| 文件所有权 | 打包/重下可能触碰用户放入任务目录的文件 | 使用 Pydantic 清单记录程序所有文件，只清理和打包清单内直属普通文件。 |
| 删除安全 | 软链接或伪造路径可能扩大删除范围 | 删除前验证记录根目录、直属子目录和符号链接；单任务失败不影响批次其他项。 |
| 完成态语义 | 数据库显示完成但文件已经丢失 | 引入 `MISSING` 状态，保留历史并允许重新下载。 |
| 退出生命周期 | Qt 退出时异步任务、封面线程和日志可能未排空 | 有界取消、等待线程、停止 UI worker，并在退出前完成 Loguru 队列。 |
| UI 时序 | 旧搜索/卡片线程结果可能覆盖新状态 | 以查询参数和 generation token 丢弃过期结果，所有工作线程有界。 |
| 删除反馈 | UI 先移除卡片、后端删除失败后状态不可见 | 后端逐项返回删除结果，UI 仅在成功后移除并显示失败原因。 |
| 导入副作用 | 导入配置/路径/下载器即写磁盘或创建全局线程 | 初始化集中到入口组合根；下载器和仓储端口由构造参数注入 UI。 |
| 工具链 | 类型和 lint 门禁覆盖不足、提交钩子依赖浮动 | 全部签名注解、严格 Pyright、扩展 Ruff 规则；本地 hook 复用 `uv.lock`。 |
| 供应链 | CI Action 标签可变、缺少依赖审计和 SBOM | Action 固定完整 SHA；CI 增加 OSV 审计和 CycloneDX SBOM 导出验证。 |

## 第二轮复审整改

- 单实例锁前移到数据库、配置、下载器和 UI 初始化之前；第二实例回归测试确认不会重置活动任务。
- 完成任务从领域层可取消状态和合法取消迁移中移除，UI 与后端共享同一状态白名单。
- 小文件写入按整本任务累计检查磁盘，图片转换后的实际输出大小纳入任务字节预算。
- 下载路径在创建前后拒绝符号链接和 Windows junction；取消时只删除清单、数据库图片记录和临时命名可证明归属于任务的文件。
- 原图地址解析异常进入退避重试；分页设置独立硬上限并按 32 页分批创建结构化并发任务。
- 打包后保留所有权清单，使关闭打包后的重新下载能够清除陈旧 ZIP。
- 直接连接除 URL/DNS 校验外再核对 curl 实际对端 IP；代理模式保留用户明确配置的代理语义。
- 封面失败始终完成回调，缓存增加 256 MiB/2000 文件配额和并发清理锁。
- 下载器、封面管理器和 UI worker 分别获得退出时间预算；Qt worker 即使超时也会安全等待结束，避免销毁仍在运行或已被 Qt 删除的 C++ 对象。
- Pyright 将测试纳入 strict 检查；仅对类型桩不完整的 Fluent UI 边界使用文件级 Unknown 诊断豁免。
- CI 固定 uv 0.12.0、增加 job 超时并将覆盖率改为统计整个包，避免只报告核心模块造成误导；EXE 构建、烟雾测试与 SHA-256 输出改为发布前在本地手动执行。
- 域名发现不再依赖发布页固定列表位置或仅匹配 `wnacg` 前缀；解析真实链接、支持当前 `wn+数字` 域名，并按多个官方发布页回退。
- 下载任务列表分页展示，每页最多保留 100 个重型 Qt 卡片；连续新增和删除由单次定时刷新合并，避免大队列持续堆积原生控件。
- 下载图片改为固定 worker 池消费待下载序列，不再按整本图片数量创建同等数量的 asyncio 任务。
- curl-cffi 流式响应在完整读取、校验异常、大小超限和任务取消时都显式关闭，防止长时间运行积累原生句柄。
- 队列徽标和状态计数使用 SQL `COUNT`，启动时只调度可用槽位一次，消除大队列反复全量读取的平方级开销。
- Windows 网络线程改用原生 Selector 事件循环，绕开 curl-cffi 在 Proactor 下额外创建的 selector 桥接线程，消除 CFFI 回调与 Qt 下载线程组合产生的 `python312.dll / 0xc0000005` 访问冲突。
- 搜索卡片状态改为 Home 页面持有的单 worker 批量快照；卡片销毁前取消旧代查询，下载、搜索、封面和设置 worker 均以 Qt 队列连接回到主线程，封面目标使用弱引用并校验 Shiboken C++ 对象有效性。
- 直链列表末尾的 `shoucang.jpg` 是站点收藏按钮而非漫画图片；解析时显式过滤，避免固定多 1 张并触发大量详情页回退请求。
